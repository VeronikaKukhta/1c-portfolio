
## 1. Главная метафора: Ресторан
*   **Клиент (Зал)** — это то, что видит пользователь на экране. У клиента есть монитор, но нет прямого доступа к базе данных (холодильнику).
*   **Сервер (Кухня)** — это мощный компьютер, где хранятся данные и выполняются все тяжелые операции (запросы, запись). У сервера нет монитора.

## 2. Где что писать? (Директивы компиляции)

В 1С код делится на две зоны с помощью директив:

###  `&НаКлиенте`
*   **Где выполняется:** На компьютере пользователя.
*   **Что можно делать:** Работать с интерфейсом (показать сообщение, открыть окно, изменить цвет, вызвать сервер).
*   **Что НЕЛЬЗЯ делать:** Делать запросы к базе, обращаться к справочникам/документам напрямую (например, `Справочники.Товары.НайтиПоНаименованию`), вызывать `ТабДок.Показать()`.
*   **Пример:** `&НаКлиенте Процедура КнопкаНажатие(Команда)`

###  `&НаСервере`
*   **Где выполняется:** На сервере (в «кухне»).
*   **Что можно делать:** Делать запросы, читать/писать в базу, выполнять сложные расчеты.
*   **Что НЕЛЬЗЯ делать:** Показывать что-то на экране (у сервера нет монитора), работать с интерфейсными элементами (например, открыть форму).
*   **Пример:** `&НаСервере Функция ПолучитьОстатки()`

###  `&НаСервереБезКонтекста`
*   Используется, когда серверной процедуре **не нужны** данные с формы (например, она просто складывает два переданных числа). Это экономит трафик и работает быстрее.

## 3. Серверный вызов (Как клиент общается с сервером)

Клиент не может напрямую обратиться к базе. Он должен «попросить» сервер.
1. Клиент вызывает серверную функцию или процедуру.
2. Платформа автоматически передает на сервер контекст (все данные формы).
3. Сервер выполняет код и возвращает результат.
4. Клиент получает результат и продолжает работу.

**Пример:**
```bsl
&НаКлиенте
Процедура КнопкаПроверить(Команда)
    // Клиент просит сервер
    Результат = ПроверитьНаСервере(); 
    Сообщить(Результат);
КонецПроцедуры

&НаСервере
Функция ПроверитьНаСервере()
    // Сервер делает запрос к базе
    Если Справочники.Товары.НайтиПоНаименованию("Ручка") = Неопределено Тогда
        Возврат "Нет такой ручки!";
    КонецЕсли;
    Возврат "Ручка найдена!";
КонецФункции
```

## 4. Модуль формы vs Модуль объекта (Золотое правило)

Это самое важное для правильной архитектуры.

###   Модуль объекта
*   **Кто это:** «Шеф-повар» на кухне.
*   **Зачем нужен:** Для **бизнес-логики**. Для правил, которые должны соблюдаться **всегда** при записи объекта.
*   **Где используется:** Проверки (нельзя сохранить без телефона), расчеты, движения по регистрам (проведение).
*   **Событие:** `ПередЗаписью`, `ПриЗаписи`, `ОбработкаПроведения`.
*   **Важно:** Неважно, как объект попал в базу (через форму, через загрузку из Excel или программно) — модуль объекта сработает всегда.

###  Модуль формы
*   **Кто это:** «Официант» в зале.
*   **Зачем нужен:** Для **интерфейса** и удобства пользователя.
*   **Где используется:** Реакция на нажатие кнопок, автозаполнение полей при выборе, пересчет суммы на экране.
*   **Событие:** `ПриОткрытии`, `ПриИзменении`, `НажатиеКнопки`.

**Главное правило:** Если правило критично для базы (нельзя сохранить плохие данные) — пиши в **Модуль объекта**. Если это просто удобство для пользователя на экране — пиши в **Модуль формы**.

##  Топ-3 ошибки новичков (и как их избежать)

1.  **Запрос к базе на клиенте.** Ошибка: `Справочники.Товары.НайтиПоНаименованию` внутри `&НаКлиенте`. Решение: Вынести в серверную функцию.
2.  **Показ печатной формы на сервере.** Ошибка: `ТабДок.Показать()` внутри `&НаСервере`. Решение: Сформировать `ТабДок` на сервере и вернуть на клиент, а показать уже на клиенте.
3.  **Проверка данных в модуле формы.** Ошибка: Запрет на запись без телефона написан в форме. Если данные загрузят из файла — проверка не сработает. Решение: Перенести проверку в Модуль объекта.
