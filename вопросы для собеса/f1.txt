1. Чем отличается справочник от документа?
Справочники 1С — специализированный объект древа метаданных, который служит для хранения статичной информации справочного характера.
Документы в 1С 8.2 и 8.3 — объект метаданных, с помощью которого в 1С фиксируются хозяйственные операции предприятия.

2. Может ли справочник быть регистратором в регистрах?
Нет. Только документ может быть регистратором.

Модуль объекта вызывается при создании нового объекта и при записи объекта.

ВОПРОСЫ СРЕДНЕГО УРОВНЯ
1. Директива по умолчанию (если не указать)?
По умолчанию, если перед процедурой (функцией) ничего не указано, то применяется директива 1С &НаСервере.

2. Для чего используют директиву  "НаКлиентеНаСервереБезКонтекста"? Какие у нее особенности?
Используется, когда к процедуре нужно обращаться и с клиента, и с сервера. В остальном аналог &НаСервереБезКонтекста.

3. Чем структура отличается от соответствия? (топ рейтинга =) )
Ключ в структуре может быть только строкой, а в соответствии может быть любым типом.

4. Какими горячими клавишами пользуетесь при разработке?
F5, F9-F11 для отладки, Ctrl+H для замены значений.

5. В какой момент отрабатывают подписки на события?После отработки события, к которому привязаны. 
После отработки события, к которому привязаны. 

6. Имеет ли значение порядок измерений в регистрах?
Да. Выше всего необходимо ставить измерения, которые будут чаще запрашиваться в системе

7. Каким способом можно отсортировать структуру?
Предполагается, что структура не нуждается в сортировке. Можно выгрузить в таблицу значений и отсортировать. 

8. Что означает флаг "Вызов сервера" у общего модуля?
Глобальный — если флаг установлен, функции и процедуры из этого модуля становятся доступны в глобальном контексте. Т.е. их можно вызвать в любом месте конфигурации, обращаясь без названия общего модуля. Однако добавляется условие — название процедур и функций в этом общем модуле должны быть уникальны в рамках глобального контекста.
Сервер — процедуры и функции данного общего модуля могут быть выполнены на сервере.
Внешнее соединение — программные коды данного общего модуля могут быть выполнены при подключении внешним источником (например, COM).
Клиент (управляемое приложение) — процедуры и функции данного общего модуля могут быть использованы в толстом клиенте в режиме управляемого приложения.
Клиент (обычное приложение) — программные коды данного общего модуля могут быть использованы в толстом клиенте в режиме обычного приложения.
Вызов сервера — флаг, разрешающий на клиенте использовать процедуры и функции из этого общего модуля.
Привилегированный — если установлена Истина, в этом общем модуле будет отключена проверка прав доступа.
Повторное использование — определяет настройки возвращаемых значений, если опция включена, то после первого выполнения система запомнит значение для данных входных параметров и будет возвращать уже готовое значение. Может принимать следующие значения: не используется — отключение, на время вызова — на время выполнения определенной процедуры, на время сеанса — пока пользователь не закрыл сеанс (программу). 

СЛОЖНЫЕ ВОПРОСЫ
БСП

1. С какими подсистемами БСП приходилось работать? Какие функции использовали?
Ответ: Чаще всего используются: «Пользователи» (управление правами, авторизация), «Варианты отчетов» (хранение и вывод отчетов), «Дополнительные отчеты и обработки» (подключение внешнего функционала без изменения конфигурации), «Версионирование объектов» (история изменений), «Групповое изменение объектов» и «Очередь заданий» (выполнение регламентных задач). Из функций активно применяются методы ОбщегоНазначения.ЗначениеРеквизитаОбъекта() для быстрого чтения данных без создания тяжелых объектов памяти.
2. Организация прав доступа в типовых конфигурациях. Что где указывается? Как работает?
Ответ: В современных типовых конфигурациях права строятся на профилях групп доступа и группах доступа. В метаданных создаются Роли, которые жестко задают базовые права на объекты. Профили объединяют несколько ролей. Самим пользователям назначаются Группы доступа, привязанные к определенному профилю. Система на лету объединяет все доступные роли пользователя по принципу «Разрешено все, что разрешено хотя бы одной ролью». Также БСП предоставляет механизм «Управление доступом» для настройки ограничений по видам доступа (организации, контрагенты) на уровне пользователей.
3. Как используется RLS в типовых? Где указывать ограничения?
Ответ: RLS (ограничение доступа на уровне записей) используется для фильтрации строк таблиц в зависимости от прав пользователя (например, «видеть документы только по своей Организации»). Ограничения указываются в свойствах Роли на закладке «Ограничения доступа» для конкретных прав (Чтение, Добавление, Изменение, Удаление). В типовых конфигурациях используется шаблонный RLS от БСП: в коде роли прописывается вызов общих шаблонов (например, #ПоОрганизации), а сами правила и связи настраиваются через регистры сведений подсистемы «Управление доступом».

Формы

4. Разница директивы &НаСервере и &НаСервереБезКонтекста?
Ответ: Главное отличие — в передаче контекста формы (данных всех реквизитов формы) между клиентом и сервером. Вызов &НаСервере передает на сервер и возвращает обратно на клиент все данные формы, что увеличивает объем сетевого трафика и нагрузку на сервер. &НаСервереБезКонтекста не передает контекст формы, работает быстрее и тратит меньше ресурсов. Его используют для вызова независимых процедур, расчетов или чтения данных из БД, когда сама форма «в сборе» на сервере не нужна.
5. Используется ли ТаблицаЗначений на форме? Что используется?
Ответ: Напрямую объект ТаблицаЗначений (тип данных базы или сервера) на управляемой форме использовать нельзя. Вместо нее на форме создается реквизит с типом ДанныеФормыКоллекция. Для отображения этой коллекции на экране используется элемент формы Таблица. При необходимости ТаблицаЗначений может быть преобразована в ДанныеФормыКоллекция и обратно с помощью методов ЗначениеВРеквизитФормы() и РеквизитФормыВЗначение().
6. Как передать значение реквизита формы в фильтр формы выбора?
Ответ: Передать значение можно через Параметры выбора (свойство элемента формы ПараметрыВыбора или программно через структуру Параметры при открытии формы метода ОткрытьФорму()). Также можно связать реквизиты через свойство элемента Связи параметров выбора. Если требуется динамическая фильтрация в момент нажатия, в обработчике события НачалоВыбора создается структура и заполняется свойство Отбор параметров открываемой формы.

Блокировки и проведение

7. Стандарты 1с по организации проведения документа. Где подготавливаются данные для проведения?
Ответ: По стандартам 1С проведение должно разделяться на два этапа. Все данные для проведения (проверка остатков, расчеты, сбор аналитики) должны подготавливаться в обработчике ОбработкаПроведения в модуле документа. Подготовка и чтение данных происходят с помощью пакетных запросов к базе данных, чтобы минимизировать количество обращений. Сама запись движений должна производиться «одним махом» в конце обработчика, либо с использованием механизма разделения управляемых блокировок до начала чтения остатков.
8. Что такое разделяемая (исключительная) блокировка? Автоматическая (управляемая) блокировка? Объектная (транзакционная) блокировка? Их связь с SQL?
Ответ:
• Разделяемая блокировка (Shared): позволяет другим транзакциям читать данные, но запрещает их изменение. Исключительная (Exclusive): запрещает и чтение (для транзакций с блокировками), и изменение данных другими транзакциями.
• Автоматический режим: блокировками СУБД управляет сама платформа на основе уровней изоляции транзакций. Управляемый режим: разработчик сам явно ставит программные блокировки с помощью объекта БлокировкаДанных, что снижает количество взаимоблокировок (Deadlocks).
• Объектная блокировка: блокирует объект от изменения на уровне бизнес-логики 1С (пессимистическая/оптимистическая блокировка при открытии формы). Транзакционная: действует строго внутри транзакции на уровне базы данных.
• Связь с SQL: Управляемые блокировки работают на специальном сервере блокировок 1С, но при записи данных платформа транслирует их в жесткие Exclusive/Intent-Exclusive блокировки на уровне таблиц СУБД (MS SQL, PostgreSQL и др.).

Индексы

9. Что такое индекс?
Ответ: Индекс — это специальная структура данных (обычно B-дерево) в СУБД, создаваемая для ускорения поиска, сортировки и выборки строк в таблицах базы данных. Индекс можно сравнить с алфавитным указателем в конце книги, который позволяет быстро найти страницу с нужным термином, не перелистывая всю книгу целиком.
10. Нужно ли использовать индексы и в каких случаях?
Ответ: Индексы использовать нужно, но избирательно. Их следует создавать для полей, которые часто используются в условиях запросов (ГДЕ), в условиях соединения таблиц (ПО) и при сортировке (УПОРЯДОЧИТЬ ПО). Индексы не нужно ставить на поля с низкой селективностью (где мало уникальных значений, например, булево «Удален»), а также на таблицы, которые постоянно перезаписываются большими объемами данных, так как каждый индекс замедляет операции записи (ЗАПИСЬ, ИЗМЕНЕНИЕ).
11. Зависимость порядка измерений регистра и индекса?
Ответ: В регистрах (накопления, сведений) платформа автоматически создает кластерный индекс. Порядок полей в этом индексе строго совпадает с порядком измерений, заданным в конфигураторе (сверху вниз) + поле Период (для периодических). От порядка измерений зависит эффективность поиска: индекс эффективно работает только тогда, когда в условиях запроса используются измерения слева направо без пропусков.
12. Будет ли использоваться индекс, если в запросе есть условие по третьему измерению регистра, все измерения в котором проиндексированы?
Ответ: Полный индекс регистра использоваться не будет (произойдет сканирование всей таблицы — Index Scan / Table Scan). СУБД не может задействовать составной индекс, если пропущены первые два измерения. Исключение: индекс будет использован только в том случае, если для третьего измерения в конфигураторе был взят отдельный флаг «Индексировать» — тогда платформа создаст для него дополнительный одиночный индекс в СУБД.

Запросы

13. Как изменить запрос в условии которого присутствует "ИЛИ"? Зачем менять?
Ответ: Запрос с оператором ИЛИ в секции ГДЕ следует переписать через ОБЪЕДИНИТЬ ВСЕ (разбить один запрос на два независимых и объединить их результаты). Менять это необходимо потому, что при наличии ИЛИ оптимизатор СУБД часто не может выбрать подходящий индекс и переходит на полное сканирование таблицы (Table Scan), что критически снижает скорость работы системы.
14. Где хранится временная таблица? Если она большая? Как индексируется?
Ответ: Временная таблица хранится на стороне СУБД в специальной системной базе данных для временных объектов (например, tempdb в MS SQL Server). Размер таблицы ограничен дисковым пространством сервера СУБД. Индексируется временная таблица программно в коде 1С с помощью конструкции ИНДЕКСИРОВАТЬ ПО... в тексте запроса менеджера временных таблиц. Индексировать большие временные таблицы нужно обязательно по тем полям, по которым далее будет происходить связь (соединение) с другими таблицами.
15. Мы получаем данные остатков из регистра накопления для проведения. В параметрах запроса нужно использовать текущую дату или МоментВремени? Почему?
Ответ: Необходимо использовать МоментВремени() (комбинация даты, времени и ссылки на документ). Если передать просто текущую дату, запрос вернет остатки на начало этой секунды, проигнорировав движения других документов, записанных в эту же секунду, либо движения самого документа, если он перепроводится. МоментВремени() гарантирует получение остатков в правильной транзакционной последовательности на точку оси времени сразу после или до текущего документа.

Транзакции

16. Почему возникает ошибка "В данной транзакции уже происходили ошибки!"? Как её избежать?
Ответ: Эта ошибка возникает, когда внутри транзакции (например, в блоке Попытка...Исключение) произошла какая-то системная ошибка базы данных (отказ блокировки, нарушение уникальности индекса), код перехватил её в Исключение, но выполнение транзакции продолжилось. Платформа 1С при первой же ошибке БД помечает всю транзакцию как обреченную на откат (Rollback). Избежать этого можно правильным проектированием: не выполнять внутри транзакций код, который заведомо может упасть по вине БД, а при перехвате ошибок в блоке Исключение обязательно вызывать отмену транзакции (ОтменитьТранзакцию()) и прекращать дальнейшие операции с базой данных в этом цикле.

Правила конвертации

17. Опишите порядок действий, если нужно организовать постоянный обмен каким-то документом между двумя различными конфигурациями, использующими БСП.
Ответ: Последовательность действий следующая:
18. Зарегистрировать обмениваемый документ в составе объекта План обмена в обеих базах (для регистрации изменений).
19. Настроить правила конвертации объектов (синхронизацию полей) в конфигурации «Конвертация данных» (КД 2.0 или КД 3.0). Если базы на БСП, рекомендуется использовать КД 3.0 (технология через формат EnterpriseData).
20. Выгрузить модули менеджера обмена из КД и вставить их в соответствующие конфигурации.
21. Включить и настроить подсистему БСП «Синхронизация данных» через пользовательский интерфейс (задать каналы обмена: каталог, FTP или COM) и составить расписание для регламентных заданий обмена.

Интеграции

18. В чём разница между web-сервисами и http-сервисами?
Ответ: Web-сервисы (SOAP) работают по строгому протоколу, используют формат XML, описываются жесткой структурой WSDL и требуют строгого соответствия типов данных (XDTO). Они сложнее в разработке, но строго типизированы. HTTP-сервисы (REST) работают на основе стандартных архитектурных методов HTTP (GET, POST, PUT, DELETE). Они более «легковесные», гибкие, не привязаны к жестким схемам и работают быстрее, передавая любые данные (чаще всего JSON или чистый текст).
19. Используется ли в web-сервисах json? А в http-сервисах?
Ответ: В классических Web-сервисах (SOAP) JSON не используется (стандарт требует строго XML). В HTTP-сервисах JSON является основным и самым популярным форматом передачи данных благодаря своей компактности и простоте разбора на любых платформах. Однако технически HTTP-сервис может принимать и отдавать любой тип контента (включая XML, файлы или бинарные данные).
20. Зачем нужен XDTO? Что такое схема xml? xsd? XPass преобразование?
Ответ:
• XDTO (XML Data Transfer Objects) — механизм 1С для представления объектных данных (документов, справочников) в виде универсальных структур для обмена с внешними системами.
• Схема XML / XSD (XML Schema Definition) — это файл-инструкция, описывающий жесткие правила и структуру XML-документа (какие поля обязательны, какие типы данных у тегов).
• XPath-преобразование (или XSLT) — язык запросов и трансформации к элементам XML-файла, позволяющий быстро находить нужные узлы или преобразовывать один XML-документ в другой без полного разбора программным кодом.
21. Как подключиться к базе SQL для чтения данных?
Ответ: Для прямого подключения к сторонней базе SQL из кода 1С используется COM-объект ADO (ActiveX Data Objects).
Код выглядит следующим образом:
bsl
Соединение = Новый COMОбъект("ADODB.Connection");
Соединение.ConnectionString = "Driver={SQL Server};Server=ИмяСервера;Database=ИмяБазы;Uid=Логин;Pwd=Пароль;";
Соединение.Open();
// Выполнение запроса
RecordSet = Соединение.Execute("SELECT * FROM Таблица");
Используйте код с осторожностью.
После получения объекта RecordSet данные считываются в цикле и переносятся в коллекции 1С.
